# v0.1 Final Release Gate / Release Candidate Freeze

Status: **RC freeze entry; public release is not authorized.**

Pre-freeze integration baseline: `main@906b38ca1211b9c5985ea9814ee1212fe6b6e7a6` after PR #33. The actual frozen RC source is the squash-merge commit of the RC Freeze PR and must be recorded only after that merge exists.

## Freeze rule

Once the RC Freeze PR is merged:

- the resulting exact `main` commit is the frozen candidate source;
- only release-blocking fixes may change the candidate line;
- feature work does not enter the frozen v0.1 candidate;
- any code/package/workflow change invalidates prior exact-source candidate evidence and requires the full gate again;
- no tag, GitHub Release, signing upload, public manifest or candidate promotion is created by the freeze itself.

`public_release_ready` remains `false` until the manual release gates below are explicitly accepted.

## Automated gate

The frozen exact-`main` commit must have all of the following:

1. **CI / push**
   - Rustfmt;
   - archive/distribution tool tests;
   - Ubuntu, macOS and Windows `cargo check --locked --workspace --all-targets`;
   - Clippy with `-D warnings`;
   - full workspace Rust tests.

2. **Managed ag-psd Package / push**
   - Linux x86_64, macOS arm64 and Windows x86_64 package jobs;
   - verified Managed engine package;
   - developer candidate layout v2;
   - extracted-candidate PSD and ten-cycle lifecycle acceptance;
   - isolated fresh-environment acceptance with all 20 expected CLI steps;
   - candidate/notice source identity equal to the exact frozen checkout;
   - prototype three-target manifest assembly.

3. **Windows Lifecycle Diagnostics / push**
   - resource attribution calibration;
   - exact-directory/remove-window/remove-file calibration;
   - bounded transport and creation-time Job controls;
   - three transport + managed diagnostic repetitions;
   - no failed-case retry, timeout widening, concurrency serialization, external unlock or unrelated-process termination.

A passing finite run does not rewrite historical failures or prove the intermittent Issue #27 OS5 root cause.

## Candidate evidence boundary

RC artifacts are validation artifacts until the manual gates are accepted. They must continue to report:

```text
redistribution_review_accepted = false
public_release_ready = false
```

The source commit/tree, target, binary SHA-256, auxiliary-file hashes and lock/toolchain inputs must remain bound in candidate metadata. Pull-request synthetic merge artifacts are not accepted as the final RC evidence; post-merge exact-`main` artifacts are required.

## Manual release gates

These require an explicit owner decision or external acceptance and cannot be inferred from green CI:

| Gate | Required decision/evidence | Freeze state |
| --- | --- | --- |
| Project license | Choose and add the project license/metadata | BLOCKED |
| Third-party redistribution | Review actual CLI + Managed engine notice payload and accept redistribution obligations | BLOCKED |
| Windows reliability risk | Resolve Issue #27 or explicitly accept a documented known-risk release policy | BLOCKED |
| macOS signing/notarization | Decide signing/notarization policy and validate downloaded/quarantined artifact on supported macOS | BLOCKED |
| Windows signing | Decide whether v0.1 requires Authenticode/code-signing and validate the chosen path | BLOCKED |
| Minimum OS / clean machine | Define supported OS floor and pass clean-machine acceptance for each published target | BLOCKED |
| Durable distribution | Choose trusted release hosting/manifests and replace prototype URLs where required | BLOCKED |
| Release authorization | Explicitly approve version/tag/publication after every preceding gate is accepted | BLOCKED |

No automatic process should silently convert one of these decisions to accepted.

## Issue #27

Issue #27 remains open. PRs #28–#37 substantially improved owned cleanup, bounded I/O, creation-time Job assignment, startup timeout classification and in-flight Windows attribution, but a spontaneous historical remove OS5 has not been causally attributed.

The RC Freeze may proceed as a source/evidence freeze while this gate remains blocked. Public v0.1 publication requires a separate explicit reliability decision.

## Exit states

The freeze has two distinct exits:

- **RC frozen / release blocked**: automated exact-source evidence is green, but one or more manual gates remain blocked.
- **v0.1 release authorized**: automated evidence is green for the same frozen source and every manual gate has an explicit accepted record.

Do not create `v0.1.0`, a public GitHub Release, or production manifests merely because the RC is frozen.
