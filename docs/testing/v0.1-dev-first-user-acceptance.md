## Final single-file transfer kit

Created a private, non-public, one-ZIP transfer kit using the exact
existing `v0.1.0-dev.5526dc4` macOS bundle:

```text
yu-v0.1.0-dev.5526dc4-mac-first-user-macos-arm64.zip
SHA-256 e6eaa689bb0bcb7581d13b1d908f489906a8b3513817ba4fa296f77c4322719d
bytes   54865165
```

Contained files:

- `README-FIRST.zh-CN.md` — Chinese five-step tester instructions;
- `First-User-Test.command` — **macOS stock Bash/tools** only, no
  Python, developer Node, Rust, Xcode or Cargo required on the test Mac;
- unchanged `yu-v0.1.0-dev.5526dc4-macos-arm64.zip` with fixed
  SHA-256 `5897360ddbc770e45232b2bbbf569cb585a88d38547105a6ae872b6e72c8e44a`;
- pinned `test-fixtures/sample.png` and `2layers.psd`;
- `MANUAL-ACCEPTANCE.md` — **unfilled** Air first-use form;
- `KIT-MANIFEST.json` and `SHA256SUMS`.

This requires only **one transfer and one manual outer extraction**.
The script verifies all nested SHA-256 values and extracts the CLI/engine
under a unique private test directory automatically.

Its version/doctor, image info/resize, PSD-before-install denial,
offline engine install/activate, PSD inspect/tree/list/export,
deactivate/remove and input-integrity checks use a **fresh isolated
YU_DATA_HOME/HOME** and only test samples, with no sudo or edits to
user PSD files. The engine is not registered to the user's normal
YuTool setup. The script records ZIP/binary quarantine metadata
*read-only* and will never remove xattrs or disable Gatekeeper.
